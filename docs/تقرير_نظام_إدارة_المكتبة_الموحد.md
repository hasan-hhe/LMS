## الملخص

يقدّم هذا المشروع **نظام LibraLMS**، وهو منصة متكاملة تجمع بين **إدارة المكتبة التقليدية** (الاستعارة، الحجز، الغرامات، المخزون) و**متجر الكتب الإلكتروني** (البيع، المحتوى الرقمي، الطلبات). يهدف النظام إلى ربط المكتبات والقراء في بيئة رقمية موحّدة تخدم ثلاث فئات:

- **تطبيق الهاتف للعضو (Member):** تصفح، استعارة، شراء، **دفع بالنقاط فقط**، وشحن الرصيد عبر **أكواد النقاط**.
- **لوحة تحكم أمين المكتبة (Librarian):** catalog، نسخ، استعارة/إرجاع، حجوزات، طلبات، غرامات، تقارير.
- **لوحة تحكم المدير (Admin):** مستخدمون، توليد أكواد شحن النقاط، قواعد التحويل، تقارير.

**نموذج الدفع المعتمد:**

| العنصر | الدور |
|--------|--------|
| **سعر الليرة السورية** | عرض وتقارير ومحاسبة مرجعية |
| **سعر النقاط** | وسيلة الدفع الفعلية داخل النظام |
| **رصيد النقاط** | الرصيد الوحيد للعضو للدفع |
| **أكواد الشحن** | تضيف نقاطاً لحساب العضو (لا تُستخدم للدفع المباشر) |

تم البناء على **Laravel 12 + PHP 8.2 + Sanctum**، تطبيق **Flutter**، ولوحة إدارة **Blade + REST API** مع **OpenAPI/Swagger**.

## الفصل الأول: مقدمة

في ظل التحول الرقمي، تحتاج المكتبات إلى منصة تجمع الفهرسة والاستعارة والبيع. يواجه القراء صعوبة في الدفع الإلكتروني محلياً، بينما يحتاج أمناء المكتبة لأتمتة العمليات.

يأتي **LibraLMS** كحل هجين:

| المصدر | ما يُضاف |
|--------|----------|
| **LMS الحالي** | استعارة، إرجاع، تمديد، غرامات، حجوزات، أعضاء، تقارير |
| **LibraX (مرجع)** | بيع، محتوى رقمي، مفضلة، إحصائيات مبيعات |
| **نموذج المشروع** | **عملة داخلية بالنقاط** + **أكواد شحن** + تسعير مزدوج (ل.س + نقاط) |

**مبدأ الدفع:** كل عملية مالية داخل التطبيق (شراء، رسوم استعارة، غرامة، تمديد) تُخصم من **رصيد النقاط**. الأكواد لا تدفع مباشرة — بل **تشحن النقاط**.

## الفصل الثاني: الدراسة المرجعية

| النظام | نقاط القوة | نقاط الضعف |
|--------|-----------|-----------|
| Koha / Evergreen | استعارة وتقارير | لا تجارة محلية بالنقاط |
| Amazon Books | بيع وتقييمات | لا استعارة فيزيائية |
| LibraX | بيع + محفظة/شام كاش | تحويل خارجي معقّد |

**تميز LibraLMS:**

1. هجين: Circulation + E-commerce.
2. **الدفع بالنقاط فقط** — قناة واحدة واضحة.
3. **أكواد شحن النقاط** بدل محفظة أو بوابة دفع.
4. كل كتاب له **سعر ل.س** و**سعر نقاط**.
5. أدوار: Admin / Librarian / Member.

## الفصل الثالث: دراسة المتطلبات

### 3.1 مشكلة المستخدم والحل

| الفئة | المشكلة | الحل |
|-------|---------|------|
| عضو | صعوبة الدفع والشراء والاستعارة | رصيد نقاط + شحن بالكود + خصم تلقائي |
| أمين مكتبة | إدارة يدوية | لوحة circulation + خصم نقاط عند الرسوم |
| مدير | رقابة مالية | توليد أكواد شحن + أرصدة + تقارير |

### 3.2 توصيف المشكلة

بدل تشتيت الدفع (كود مباشر + كوبون + نقاط)، يعتمد النظام **عملة واحدة داخلية = النقاط**:

1. الإدارة تولّد أكواد شحن (كل كود = عدد نقاط).
2. العضو يشحن رصيده بإدخال الكود.
3. عند الشراء/الغرامة/الرسوم يُخصم من الرصيد.
4. السعر بالليرة للعرض؛ الدفع بالنقاط.

### 3.3 المصطلحات

| المصطلح | التعريف |
|---------|---------|
| **سعر الليرة (price_syp)** | سعر الكتاب/الغرامة بالليرة السورية — للعرض والتقارير |
| **سعر النقاط (price_points)** | ما يُخصم من رصيد العضو عند العملية |
| **رصيد النقاط** | رصيد العضو الداخلي للدفع |
| **كود شحن النقاط (Top-up Code)** | رمز يضيف نقاطاً للحساب عند تفعيله |
| **معدل التحويل** | علاقة مرجعية ل.س ↔ نقاط (مثلاً 100 ل.س = 1 نقطة) — قابلة للضبط من Admin |
| **Borrowing / Fine / Order** | عمليات تُسعَّر بالليرة والنقاط وتُدفع بالنقاط فقط |

### 3.4 قاعدة التحويل (مرجع افتراضي)

| ل.س | نقاط |
|-----|------|
| 100 | 1 |
| 1,000 | 10 |
| 25,000 | 250 |

> يُضبط المعدل من Admin في `point_settings`. عند تغيير المعدل تبقى الأسعار المخزّنة على الكتب (`price_points`) سارية ما لم تُحدَّث يدوياً أو بإعادة حساب جماعي.

## الفصل الرابع: التصميم التقني

### 4.1 نموذج الدفع (ملخص)

```
[Admin] يولّد أكواد شحن (قيمة بالنقاط)
        ↓
[عضو] يشحن الكود → يزيد رصيد النقاط
        ↓
[شراء / غرامة / رسوم استعارة / تمديد]
        ↓
خصم من رصيد النقاط فقط
```

### 4.2 الصفوف الأساسية

```
User ──< user_points (balance)
User ──< point_transactions (top_up | spend | reward | adjust)
User ──< top_up_codes (via redeem)
Book (price_syp, price_points)
Order / LateFine / Borrowing (amount_syp, amount_points, paid_with_points)
```

### 4.3 الجداول

#### موجودة (LMS)

`users`, `books`, `book_instances`, `borrowings`, `borrowing_editions`, `late_fines`, `reservations`, `orders`, `order_items`, `reviews`, authors/categories/publishers, lookup states.

#### مقترحة (نموذج النقاط)

| الجدول | الغرض | حقول رئيسية |
|--------|-------|-------------|
| `books` *(تحديث)* | تسعير مزدوج | `price` أو `price_syp`, **`price_points`** |
| `user_points` | رصيد | user_id, balance |
| `point_transactions` | دفتر حركات | user_id, points (+/-), type (`top_up`/`spend`/`reward`/`adjust`), reference_type, reference_id, note |
| `top_up_codes` | أكواد الشحن | code, points_value, user_id (nullable), is_used, expires_at, used_at, used_by |
| `point_settings` | إعدادات | syp_per_point، reward_return_on_time، fine_per_day_*، loan_period_days، membership_points، membership_days |
| `favorites` | مفضلة | user_id, book_ISBN |
| `digital_assets` | رقمي | book_ISBN, pdf_url, audio_url |

**حقول مالية على العمليات:**

| الجدول | إضافات |
|--------|--------|
| `late_fines` | `amount_syp`, `amount_points`, `is_paid`, `paid_at` |
| `borrowings` | `borrowing_cost_syp`, `borrowing_cost_points`, `is_paid` |
| `borrowing_editions` | `tax_syp`, `tax_points` |
| `orders` / items | `total_syp`, `total_points`, `paid_at` |

> **لا جداول كوبونات** في هذا النموذج.

### 4.4 قواعد العمل للنقاط

1. الدفع داخل التطبيق = خصم من `user_points.balance` فقط.
2. الأكواد = شحن فقط (`top_up`)، استخدام مرة واحدة.
3. لا يُسمح برصيد سالب؛ إن الرصيد غير كافٍ تُرفض العملية مع توجيه للشحن.
4. Admin يمكنه `adjust` مع تسجيل السبب.
5. مكافأة الإرجاع في الوقت اختيارية ومضبوطة من `point_settings`.
6. عند عرض الكتاب: إظهار السعرين معاً دائماً.

## الفصل السادس: الخاتمة

نُفّذ **LibraLMS** كنظام تسليم جاهز يجمع:

1. إدارة مكتبة كاملة: فهرس، نسخ إعارة، استعارة واحدة، حجوزات، غرامات تراكمية، تقارير.
2. متجر بالنقاط: مخزون بيع منفصل، طلبات بمهلة استلام 48 ساعة، استرداد عند الإلغاء.
3. **عملة داخلية بالنقاط** للشراء والغرامات والتمديد والعضوية؛ التحصيل النقدي للغرامات متاح لأمين المكتبة.
4. **أكواد لشحن النقاط فقط** — لا دفع مباشر بالكود.
5. **تسعير مزدوج:** ليرة للعرض والتقارير، نقاط للدفع، مع نقاط استعارة اختيارية لكل كتاب.
6. ثلاث واجهات متزامنة: تطبيق العضو، تطبيق الأمين، لوحة الويب.
